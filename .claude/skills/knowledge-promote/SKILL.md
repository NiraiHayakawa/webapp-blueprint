# knowledge-promote — 記憶の書き戻し

設計の正本は [docs/plan/Template/20260807_template-design.md](../../../docs/plan/Template/20260807_template-design.md) §7「記憶レイヤー」。原則11（知見の還流）の「書き戻し」要素の受け皿。

## 0. この skill が解く問題

`docs/` + blume MCP で「検索」は揃っている。欠けているのは**書き戻しの強制**であり、この skill はその欠落を埋める。**machine-local な auto memory はあくまで候補であり、正本ではない**（原則11 ②）。昇格していない記憶は、他のエージェント・他のマシンからは見えない。

外部の memory 製品（mem0 / Zep / Letta 等）は導入しない。保存先が無いのではなく、還流が無いのが問題だから。この skill が還流そのものを担う。

## 1. 昇格候補を抽出する

1. machine-local な auto memory（例: Claude Code の `memory/MEMORY.md`、あるいは実行中のエージェントが持つ同種の自動記憶ファイル）を読む
2. 直近のセッション・直近の diff（`git diff` / `git log` の該当範囲）と突き合わせ、次の問いだけで候補を絞る:

   > **この知見を見落とした次のエージェントは、どのタスクで失敗するか?**

3. 「失敗する」と言えない候補は捨てる。単なる作業ログ・一度きりの事情は昇格しない（第二の正本を作らないため。原則11 ②）

## 2. 置き場所を `docs-triage` にかける

抽出した候補ごとに `docs-triage` skill の分類質問を通し、行き先を決める。

- 昇格先の**既定は `docs/`**（`docs/principles/` / `docs/recipes/` / `docs/design/` / `docs/adr/` のどれかは docs-triage §2 の三層判定に従う）
- ルート `AGENTS.md` への昇格は**コンテキスト予算の対象**（docs-triage §4）。「なぜ on-demand（`docs/`）ではなく常時ロードが必要か」を書けない候補は `docs/` に留める
- 手順知識（skill 化3テストに合格するもの）は `.claude/skills/` へ。昇格後は `mise run sync:agents` を実行し、`.agents/skills/` の再生成を忘れない

## 3. 人が承認するまで書かない

**候補を書く前に、必ず人に提示して承認を得る。** 自動抽出をそのまま正本に書き込まない。

提示する内容:

- 候補ごとの知見の要約（1〜2文）
- docs-triage による判定結果（行き先ファイル）
- 既存の記述と衝突・重複しないか（衝突する場合は追記ではなく該当箇所の更新であることを示す）

承認を人に持たせる理由: レビューを経ていない記述が規範の顔をして増殖すると、原則5（決定ログと現行規範の二層モデル）が崩れる。**記憶は候補、正本は昇格したものだけ**という非対称を、承認ゲートで維持する。

- [ ] 承認前に候補・行き先・衝突有無を提示したか
- [ ] 承認を得るまで `docs/` や `AGENTS.md` へ書き込んでいないか

## 4. 承認後に書く

- 承認された候補だけを、docs-triage が決めた場所に書く。新しい「記憶」専用ファイルを作らない（正本は既存の docs 構造の中にある）
- 既存ファイルへの追記か上書きかは docs-triage の判定に従う（例: ルート `AGENTS.md`「現在の状態」節は上書き専用）
- skill を新規作成・変更した場合は `mise run sync:agents` を実行し、続けて `mise run check:agents` で drift が無いことを確認する
- ADR を追加・変更する内容であれば `adr` skill の索引更新・対応規範ファイル更新の同梱ルールに従う

## 5. 鮮度は別レイヤーが機械検証する

書き戻した後の正本の鮮度（言及するパス・コマンドの実在性、参照先が変わったのに正本が触られていないこと）は `tests/policy/` の policy-as-test が検証する（原則11 ②）。この skill の責務は「書き戻すこと」までであり、鮮度維持そのものは対象外（機械強制済みのルールをここに重複させない）。

## 6. チェックリスト

- [ ] 昇格候補は「次のエージェントが知らないと失敗するか」で絞ったか（単なる作業ログを含めていないか）
- [ ] `docs-triage` skill で行き先を判定したか
- [ ] ルート `AGENTS.md` への昇格を提案する場合、常時ロードが必要な理由を書いたか
- [ ] 書き込み前に人の承認を得たか（自動抽出をそのまま書いていないか）
- [ ] skill を変更した場合、`mise run sync:agents` を実行したか
