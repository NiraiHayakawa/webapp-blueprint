# adr — 決定ログの記録

設計の正本は [docs/plan/Template/20260807_template-design.md](../../../docs/plan/Template/20260807_template-design.md) §6「docs 配置」。原則5（決定ログと現行規範の二層モデル）・原則11（知見の還流）の受け皿。

## 1. ADR を書くとき

`docs-triage` skill の分類質問（「見落としたら失敗するタスクは?」）で「なぜ?」を問い直すときのみ必要と判定された情報が対象。次のいずれかに当たるなら ADR を書く。

- 複数の選択肢を比較し、1 つを採用して他を捨てた（捨てた理由が将来また問われる）
- 既存の決定（別の ADR）を上書き・撤回する
- 前提が変わって過去の却下判断を覆す（テンプレート自身に前例がある: DDD 戦術パターンの採否が「LLM 以前」と「LLM 以後」で逆転した件。設計の正本 §3 を参照）

「今どうやっているか」だけの記述は ADR ではなく `docs/design/` か `docs/recipes/`（`docs-triage` §2 参照）。

## 2. 命名とファイル形式

- 連番 `NNNN`（4 桁、ゼロ埋め）+ kebab-case: `docs/adr/NNNN-kebab-case-title.md`
- **日付ベースの命名は使わない**。連番は「ADR 0009 決定 2」のような相互参照 ID として安定する。日付は本文のメタ情報として書く
- 次の番号は `docs/adr/README.md` の索引表から採番する（既存の最大値 + 1）。並行 PR での番号衝突は index の更新を先に取り込んだ側を正とし、後追いは採番し直す

テンプレート（本文の節構成）:

```markdown
# NNNN: タイトル

- 日付: YYYY-MM-DD
- 状態: 採用 | 廃止（→ NNNN で上書き）

## 文脈

なぜこの決定が必要になったか。

## 決定

何を決めたか。手順・表そのものは持たず、正本（skill / docs/principles / docs/recipes）へのリンクで済ませる。**手順を ADR に複製しない**（drift の元。docs-triage §3 卒業3テストが適用できる内容なら skill 側が正本）。

## 理由と捨てた代替案

- 代替案 A: なぜ採らなかったか
- 代替案 B: なぜ採らなかったか

## 影響

この決定によって、他のどのファイル・規範・skill の更新が必要になるか。
```

## 3. 索引の更新を同梱する

`docs/adr/README.md` は索引表 + このテンプレートを持つ正本。ADR を追加・変更する PR は次を同じ PR に含める。

- [ ] `docs/adr/README.md` の索引表に行を追加・更新した（番号 / タイトル / 状態へのリンク）
- [ ] 新規 ADR 本文を上記テンプレートの節構成で作成した

## 4. 廃止（撤回・上書き）の扱い

決定を撤回・上書きするとき、**古い ADR ファイルは削除しない**。

1. 古い ADR の「状態」行を `廃止（→ NNNN で上書き）` に変える（NNNN は上書きした新しい ADR の番号）
2. 新しい ADR の「文脈」に、どの ADR を何の理由で上書きするかを書く
3. 索引表の両方の行を更新する（古い方の状態列も書き換える）

由来: 廃止 ADR を残す運用により、「なぜ前回は採らなかったか」が後から再判断可能なまま残る。DDD 戦術パターンの採否のように、前提が変わって却下判断が覆るケースを追跡できるようにするための規律。

## 5. 対応する規範ファイルの更新を同梱する（原則11: 知見の還流）

**ADR だけを更新して終わらない。** ADR が指す実体（規範・原則・レシピ）が ADR と同じ PR で更新されていることを、`tests/policy/` の鮮度検査が機械的に見る（原則11 ②「同一 PR 内で参照先が変わったのに正本が触られていなければ落とす」）。

ADR を追加・変更したら、次のどれに影響するかを `docs-triage` skill の判定フローで特定し、同じ PR で更新する。

| ADR の内容                           | 同梱すべき更新                                                                    |
| ------------------------------------ | --------------------------------------------------------------------------------- |
| 普遍規範の追加・変更                 | ルート `AGENTS.md`「絶対規約」節                                                  |
| ディレクトリ限定の規約               | 対応する nested `AGENTS.md`                                                       |
| 「何が満たされていれば準拠か」の変更 | `docs/principles/` の対応ファイル                                                 |
| 「今どのツールでどう満たすか」の変更 | `docs/recipes/` の対応ファイル                                                    |
| 手順知識の追加・変更                 | 対応する `.claude/skills/*/SKILL.md`（`mise run sync:agents` の再生成を忘れない） |

更新すべき対象が無い（純粋に「今回は変更しない」という決定など）場合は、ADR の「影響」節にその旨を明記する。**空欄のまま「無し」と書かずに済ませない**（鮮度検査は「参照先が実在するか」までしか機械化できないため、「本当に更新不要か」の判断はレビュー観点として残る）。

## 6. チェックリスト

- [ ] `docs/adr/README.md` の索引を同じ PR で更新した
- [ ] 連番は既存の最大値 + 1 を使った（日付ベースにしていない）
- [ ] 決定の理由だけでなく、捨てた代替案とその理由を書いた
- [ ] 上書き・撤回の場合、古い ADR を削除せず状態を「廃止（→ NNNN で上書き）」に変えた
- [ ] 対応する規範ファイル（AGENTS.md / 原則 / レシピ / skill）の更新を同じ PR に含めた、または「影響」節に更新不要の理由を書いた
