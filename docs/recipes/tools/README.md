# ツールカタログ: 索引

## これは何か

`docs/recipes/tools/` 配下の各ファイルは、**テンプレートが採用していないものも含めた、ツール選択肢の記録**である。言語・領域ごとに 1 ファイルを持ち、各ツールについて「何をするか」「いつ要るか」「テンプレの採否（未採用なら理由つき）」を必ず書く。

**このカタログに載っていること自体は、テンプレートがそれを採用していることを意味しない。** 採否は各ファイルの表に個別に書いてある。「検討して採らなかった」という記録も、「採用した」という記録と同じ重みでここに残す。

## なぜあるか

1. **段階的開示**: 常時ロードされるのは [`AGENTS.md`](../../../AGENTS.md) だけである（§7「コンテキスト予算」）。ツールカタログはそこには置かず、その言語・領域に実際に手を出すときに `docs/` から on-demand で引く。カタログの中身を `AGENTS.md` に要約し直さない
2. **同じ調査を繰り返さない**: 「このツールは検討したか」を毎回ゼロから調べ直さずに済むようにする。検討済みの選択肢とその却下理由を先に読めば、同じ比較を再現しなくてよい

## 追加するときの規約

新しいツールを検討したら、**採否にかかわらず**該当ファイルの表に追記し、この README の索引が指す範囲から外れていないかを確認する。

- **未採用なら理由を必ず書く。** 原則 4「規約は機械で縛る」の「抑制には理由を書く」と同じ発想を、ツール選定そのものにも適用する — 「検討して見送った」という判断は、後から同じ検討を繰り返させないための記録として、採用判断と同じ価値を持つ
- バージョンや機能を推測で書かない。一次情報（公式リポジトリ・公式ドキュメント）で確認するか、確認できなければ「未確認」と明記する
- 各ファイルの記述は§1「三層構造」のレシピ層に属する。原則層（`docs/principles/`）にツール名を書き戻さない
