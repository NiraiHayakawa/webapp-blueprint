# 契約層レシピ: TypeSpec → OpenAPI → zod 生成

原則: [`docs/principles/contract-is-ssot.md`](../../principles/contract-is-ssot.md)（契約が単一の真実源）

このレシピは**手順と設定の雛形までを持ち、動く最小 API は持たない**。理由は `protobuf-connectrpc.md` と同じで、動く例を同梱すると契約層の選択スロットが事実上固定されるためである。

## 向いているとき

- HTTP API が主で streaming が不要
- TS エコシステムに素直な構成にしたい

## ツールとバージョン(2026-08-08 に npm registry で確認)

| パッケージ            | バージョン | 役割                                                          |
| --------------------- | ---------- | ------------------------------------------------------------- |
| `@typespec/compiler`  | 1.14.0     | `.tsp` を解析する TypeSpec コンパイラ                         |
| `@typespec/openapi3`  | 1.14.0     | TypeSpec から OpenAPI 3 を出力するエミッタ                    |
| `@hey-api/openapi-ts` | 0.99.0     | OpenAPI 3 から zod スキーマ + TanStack Query フックを生成する |
| `msw`                 | 2.15.0     | テストでの HTTP モック                                        |

`openapi-zod-client`(1.18.3)も同じ用途で存在するが、直近の公開が 2025-02-10 であり 1 年以上更新が無い(2026-08-08 時点)。`@hey-api/openapi-ts` は zod スキーマと TanStack Query フックの両方を 1 つのジェネレータで生成でき、直近も活発に更新されているため、こちらを既定にする。

すべて `pnpm-workspace.yaml` の `catalog:` に完全 pin で宣言する(原則10)。

## 手順

1. `contract/typespec/` に `.tsp` を置く
2. `tsp compile` で OpenAPI 3(JSON)を出力する。**この出力先は `contract/openapi/lock/` のような lock ディレクトリとしてコミットする。** これは「実装層の生成物」ではなく、契約そのものを別の記述形式に変換した**契約の別表現**であり、`pnpm-lock.yaml` が `package.json` の解決結果を固定するのと同じ位置づけで扱う
3. `@hey-api/openapi-ts` は、その lock ディレクトリの OpenAPI 3 を入力にして zod スキーマ + TanStack Query フックを生成する。**この生成コードはコミットしない**(`.gitignore` に加える)。ここが原則1の「生成物を持たない」が直接効く層である
4. `mise.toml` に 2 段の task を切る:
   - `contract:compile`: `.tsp` → lock ディレクトリの OpenAPI 3 (差分検査の対象)
   - `contract:generate`: lock ディレクトリの OpenAPI 3 → zod / フック(`.gitignore` 済みなので差分検査の対象にしない)
5. CI で `contract:compile` を実行した直後に `git diff --exit-code contract/openapi/lock` を走らせる。差分があれば「`.tsp` を変更したのに再コンパイルし忘れた」か「lock ディレクトリを手で編集した」のいずれかであり、どちらも止める対象になる

## 原則1(契約が単一の真実源)の要件をどう満たすか

| 要件                                     | このレシピでの実現                                                                                                                                                                                                                                                                            |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 生成物を持たない                       | zod / TanStack Query フック(実装層)はコミットしない。コミットするのは `.tsp`(契約そのもの)と lock ディレクトリの OpenAPI 3(契約の別表現、後述)だけである                                                                                                                                      |
| ② drift を検出して止める                 | `contract:compile` → `git diff --exit-code` の形で drift を検出する。protobuf レシピとは異なり、こちらは lock ディレクトリという committed な比較対象を持つため、diff ベースの検出が使える                                                                                                    |
| ③ 破壊的変更を機械ブロックする           | このレシピはこの表に破壊的変更検出の具体的な仕組みを持たない。`buf breaking` に相当する OpenAPI 用のツール選定は、このレシピが持つ雛形の範囲外である。**採用するプロジェクトは、破壊的変更検出の手段を別途選定する必要があることを ADR に明記すること**(推測で埋めていない箇所として報告する) |
| ④ 契約と実装を同じ PR で原子的に変更する | protobuf レシピと同じくレビュー運用の話であり、ツールが強制するものではない                                                                                                                                                                                                                   |

lock ディレクトリを「契約そのもの」の一部として扱ってよいか、という判断について: `.tsp` が唯一の手書き入力であり、lock ディレクトリはそこから決定的に導出される。導出結果を固定して差分検査の対象にする行為は、`pnpm-lock.yaml` を `package.json` から決定的に導出しつつコミットしているのと同型であり、「実装層の再生成可能なコード」とは区別できる。

## テストでの外部境界の扱い

`docs/plan/Template/20260807_template-design.md` §4 の通り、HTTP モック(`msw`)または pin した統合フィクスチャを使う。protobuf レシピが「モックライブラリを入れない」を選べるのは契約から型が生成されるためだが、こちらは HTTP という契約を持たない境界の上でリクエスト / レスポンスを模倣する必要があるため、モックを使う。

## 落とし穴

- lock ディレクトリの diff 検査を CI の入口に置き忘れると、`.tsp` の変更と OpenAPI 3 の不一致が本番までブロックされずに通過する。protobuf レシピが「生成物を持たないことで drift 自体を発生させない」のに対し、このレシピは「発生した drift を検出する」方式であるため、検出の配線を忘れると原則1の②が満たせなくなる
- `@hey-api/openapi-ts` の生成先を誤って `.gitignore` から外すと、実装層の生成物がコミットされてしまう。lock ディレクトリ(契約の別表現、コミットする)と生成コード出力先(実装層、コミットしない)を同じディレクトリに混在させないこと
