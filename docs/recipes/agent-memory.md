# レシピ: 外部の記憶製品を採らない判断の記録

原則: [`docs/principles/knowledge-flows-back.md`](../principles/knowledge-flows-back.md)(知見は正本へ還流する)

このファイルは原則の要約ではなく、原則が下した「外部の記憶製品(mem0 / Zep / Letta 等)は導入しない」という判断について、**同じ調査を繰り返さないため**に検討した選択肢と却下理由を記録する調査ログである。レシピ層に置くのは、この分野の製品・パターンが数ヶ月で入れ替わる寿命の短い情報だからである(2026-08-08 に調査・確認)。

## 検討した選択肢

### 1. Memory Bank パターン(コミュニティ発、複数ファイル構成)

Cline コミュニティが広めた、`memory-bank/` 配下に `projectbrief.md` / `activeContext.md` / `systemPatterns.md` 等の複数 Markdown ファイルを置き、セッション開始時にエージェントへ読ませる構成。

複数ファイルであれ単一ファイルであれ、**自動生成・自動更新される記憶をレビューなしに正本として扱う**という設計そのものが原則11の②（記憶は候補、正本は昇格したものだけ）に反するため、採らない。

### 2. MCP メモリサーバー各種

Model Context Protocol の公式 `@modelcontextprotocol/server-memory` を含む複数の MCP メモリサーバーを調査した。

**確認できた事実**: 公式 memory server の既定の保存先は `memory.jsonl` で、実行環境ローカルのファイルパスに保存される。`MEMORY_FILE_PATH` 環境変数で保存先を変更できるが、既定のまま使えば実行環境(マシン)に紐づき、リポジトリと一緒に持ち運べない。`MEMORY_FILE_PATH` をリポジトリ配下に明示的に向ければコミットできる状態にはできるが、その場合は「レビューを経ずに自動更新される記憶を正本として扱う」という原則11の②の問題が別の形で再発する(ファイルの物理的な場所がリポジトリ内に移るだけで、昇格に人間の承認を挟む仕組みには変わらない)。

調査した他の MCP メモリサーバー実装も、同様に「マシンローカルな永続化」を既定にしているものがほとんどで、複数ツール(エージェント実行環境)をまたいで同じ記憶を引く、という個別のマシンを超えた共有には別途の配線が必要になる。

### 3. 大手ベンダーの記憶機能

**GitHub Copilot Memory**(2026-08-08 時点、GitHub 公式ドキュメント・changelog で確認): リポジトリ単位で記憶を保存し、Copilot の複数機能(コーディングエージェント・コードレビュー等)間で共有する。組織・エンタープライズの policy 設定で有効化を管理できる。記憶は**既定で 28 日で自動失効**する。

**Devin Knowledge**(2026-08-08 時点、公式ドキュメントで確認): Knowledge 項目は**組織単位で共有**され、Devin が関連する Knowledge を自動的に適用する。特定リポジトリに pin することも、全リポジトリに適用することもできる。

両者は「自動生成された記憶を既定でチーム・組織の共有範囲に置く」系列であり、`docs/principles/knowledge-flows-back.md` の「業界の立場」が述べる 2 系列のうち後者に当たる。本テンプレートは前者(記憶は個人・ローカルに閉じ、正本は人間が明示的に書くファイルに限る)を採るため、これらの製品が持つ「自動 → 共有」の既定動作は、そのままでは原則11の②と衝突する。

## 要点

- **欠けているのは保存先ではなく還流の強制である。** 上記 3 系統はいずれも「どこかに記憶を保存する」までは解決するが、「保存された記憶を、人間の承認を経て正本へ昇格させる」という手順を強制する仕組みは持たない(大手ベンダー製品は逆に、承認を経ずに正本相当の共有範囲へ既定で流し込む)
- 保存先を追加で導入しても、正本が古くなる問題(原則11)は解けない。むしろ「その保存先自体が第二の正本になる」リスクを増やす
- 導入を検討し直す条件は「複数ツールをまたいで同じ記憶を引きたい」という具体的な困りごとが出たときであり、そのときの最小手は MCP 公式の memory server(ローカル JSON)である。これは上記の調査で確認した「マシンローカルが既定」という制約を理解した上で、その制約が問題にならない使い方(単一マシン・単一ツールでの補助的な下書き置き場)に限って使う、という意味である
