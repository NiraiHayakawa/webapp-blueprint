# 依存は完全固定する

## 要件

1. アプリケーションの依存・開発時だけ使う依存・ビルドに使う道具・実行環境のイメージのすべてを、範囲指定（「これ以上のバージョン」のような指定）や「常に最新」を意味する指定を使わず、完全に固定したバージョンで指定する。実行環境のイメージは、固定した名前（タグ）または内容そのものを指すハッシュ値（ダイジェスト）のいずれかで、指し示す内容が後から変わらない形に固定する
2. 新しく公開されたバージョンには、採用までの待機期間を置く（既定は公開から 7 日間）。公開直後に取り下げられるバージョンや、供給網を狙った攻撃の初動を避けるための待機である
3. セキュリティ上の修正を含む更新は、この待機期間を迂回してよい
4. 依存の更新は自動で提案され、実際に取り込むかどうかは人間が判断してマージする。自動で取り込まれることはない

## 機械強制の受け皿

- 依存を固定する方針そのもの（範囲指定が残っていないか、実行環境のイメージが再現可能な形で固定されているか）を、設定ファイルとロック情報を解析するテストとして検証する
- ロック情報の整合性検査を検証の入口の最初に置き、他のすべての検証がそれに依存する形にする（依存関係が壊れた状態で以降の検証を走らせても意味がないため）
- 更新の提案を自動生成する仕組みを設定し、待機期間とセキュリティ更新の迂回条件をその設定に反映する

## レビュー観点

- 待機期間を外して採用する判断をしたとき、その理由（セキュリティ上の緊急性など）が変更の記録に書かれているか
- 固定したバージョンを上げる判断は、動作確認を経てからマージされているか。自動提案をそのまま無条件に取り込んでいないか

## 待機期間の設定根拠

待機期間の既定値（7 日間）は、新規公開直後のサプライチェーン攻撃や重大なリグレッションが発覚・報告されるまでの猶予を確保するための安全期間として設定している。
