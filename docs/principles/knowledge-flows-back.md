# 知見は正本へ還流する

## 背景

決定ログと現行規範の二層モデル（原則 5）は「どこに書くか」を決める。しかし、**書く行為そのものには機械強制がない**。作業中に得られた知見は、その場限りの記憶（実行環境のローカルな記憶や、その時のやり取りの中）に留まりやすく、正本（決定ログ・現行規範）へ書き戻される保証がない。この非対称を放置すると、正本は書かれた時点から静かに古くなっていく。

## 要件

1. 作業で得た知見が、その場限りの記憶に留まらず、リポジトリの正本（決定ログ・現行規範）へ昇格する経路が存在する
2. 昇格していない記憶は「候補」であり、正本ではない。ローカルな記憶をそのまま正本と同格に扱い、**第二の正本**を作らない
3. 正本の記述が実体から乖離していないことが、機械的に検査される

②が要点である。自動的に生成・蓄積された記憶をレビューを経ずに正本へ流し込むと、レビューを通っていない記述が正本の顔をして増殖し、二層モデルが崩れる。**記憶は候補、正本は昇格したものだけ**という非対称を保つ。この非対称を保つ以上、昇格には人間の承認を介在させる。

## 機械強制の受け皿

- 正本が言及する対象（パス・コマンド等）の実在性を検査し、存在しない参照先を検出したら落とす
- **同じ変更のまとまりの中で参照先が変わったのに、正本側の記述が変更されていない場合**を検出して落とす。これが最も重要な検査であり、正本の記述と実体が同時に変わることを構造的に強制する
- 記憶の昇格（その場限りの記憶から正本への書き戻し）を行うきっかけを、特定の作業の種類に紐づいたトリガー可能な手順（手順知識の単位）として持つ

## レビュー観点

- この作業で得た知見のうち、次に同じ作業をする者が知らないと失敗するものは何か。それは正本のどこに昇格されるべきか
- 昇格の候補として上がった記述は、正本の既存の記述と矛盾していないか。矛盾していれば、それは古い方の記述を先に直すべきサインである

## 規範ファイルは強制ではなく文脈である

現行規範ファイル（原則 5）は、実行の起点で内容が渡されるだけの情報であり、必ず守られることを保証する仕組みではない。ある種のコーディングエージェントの公式な説明では、規範ファイルは「モデルが判断する際の文脈」として扱われるものであり、モデルの判断に関わらず確実に動作を止めたい場合は、規範ファイルとは別の強制レイヤー（実行そのものに介入する仕組み・検査・テスト）を使うべきだと明言されている。

これは原則 4（規約は機械で縛る）が言っていることと同じである。**規範ファイルに書けば守られる、という期待を持たない**ための一次情報として、この位置づけをここに記録する。規範ファイルの役割は「知っておくべきことを伝える」ことまでであり、「確実に止める」ことは別の層の仕事である。

## 業界の立場

自動生成された記憶を正本としてどう扱うかについて、コーディングエージェント各社の立場は割れている。一方の系列は、自動記憶を個人・実行環境ローカルの範囲に閉じ、チームで共有する正本は人間が明示的に書くファイルに限定する。もう一方の系列は逆に、自動生成された記憶を既定でチーム・組織の共有範囲に置く。記憶機能をコア機能として持たず、外部の仕組みに委ねる立場もある。

本テンプレートは前者（自動記憶をローカルに閉じ、正本は明示的に書いたものに限る）を採る。正本の記述はレビューを経たものだけである、という原則 5 との一貫性を優先するためである。

## 記憶レイヤーの構成

記憶の仕組みを「保存」「検索」「書き戻し」「鮮度」の 4 要素に分けたとき、本テンプレートが備えるのは以下の 4 つである。

| 要素     | 内容                                                                 |
| -------- | -------------------------------------------------------------------- |
| 保存     | 正本（決定ログ・現行規範）と、実行環境ローカルな候補としての記憶     |
| 検索     | 正本を実行時に引ける経路                                             |
| 書き戻し | 候補から正本への昇格を、人間の承認を介して行う手順知識の単位         |
| 鮮度     | 正本が実体から乖離していないことの機械検査（上記の機械強制の受け皿） |

外部の専用記憶製品は導入しない。理由は記憶の保存先が欠けているからではなく、**欠けているのは還流を強制する仕組みだから**である。保存先だけを増やしても正本が古くなる問題は解けず、むしろ第二の正本ができて二層モデルが壊れる。

鮮度の判定に時間経過（一定日数が経過したら失効とみなす）は採用しない。使われていないことと古いことは別であり、正本にとっては経過時間よりも「参照先が変わったのに正本が追随したか」という変更イベントの方が適した信号である。
