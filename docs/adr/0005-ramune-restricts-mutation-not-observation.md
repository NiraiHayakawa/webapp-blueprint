# 0005. ramune が縛るのは変更であって観測ではない

- 状態: 採用
- 決定日: 2026-08-12

## 文脈

ramune モードの稼働判定は `.ramune/graph.json` の `session.active` を見る（[ADR 0003](0003-ramune-mode-session-field.md)）。hook はこのファイルを読み、判定できない場合は安全側に倒して拒否する。

この「判定できない」の範囲が広すぎた。hook はファイルの内容を `isGraphShape`（グラフ全体の形の検査。ノード配列・エッジ・不変条件まで見る）で検証しており、**`session.active` 以外の部分が形不正になっただけでも「判定不能」として全ツール呼び出しを拒否していた**。

実際に事故になった。グラフモデルにフィールドを追加する変更を入れた際、既存のグラフファイルが新しい形を満たさなくなり、`session.active` が `false`（= 縛る必要がない状態）であったにもかかわらず hook が `Edit` / `Write` / `Bash` のすべてを拒否した。**開発中の worktree が停止し、そのファイルを直す手段自体も拒否されていたため自力で復帰できなかった。**

もう 1 つ、別の形で同じ性質の問題があった。Planner の `tools` に `Read` / `Grep` / `Glob` が無く、**仕様書も ADR も既存の実装も読めないまま**ゴールを分解していた。読めないので、依存順序をゴール文字列と要約だけから推測して組む。これは推測で仕様の穴を埋める行為であり、[原則2](../principles/fail-fast.md) が禁じているものそのものである。

## 決定

**hook が読むのは `session.active` だけにする。** グラフ全体の形は検証しない。`packages`（`tools/ramune/graph`）に `findSessionActive(value): boolean | undefined` を追加し、hook はこれだけを使う。`isGraphShape` は MCP サーバー側のストア（グラフを書き換える経路）に残す。

判定は次の 3 通りに絞られる。

| `.ramune/graph.json`                                         | 判定                     |
| ------------------------------------------------------------ | ------------------------ |
| ファイルが無い / JSON が壊れている / `session.active` が無い | 判定不能（拒否）         |
| `session.active` が `true`                                   | 稼働中（役割を強制する） |
| `session.active` が `false`                                  | 非稼働（判定を下さない） |

**Planner に `Read` / `Grep` / `Glob` を与える。** 計画のためにリポジトリを読むのは変更ではない。読まずに分解させることは、推測で計画させることと同じである。

**この 2 つは同じ原則の 2 つの側面である**: ramune が構造的に縛るべきなのは**変更**（グラフを書き換える・ファイルを書く）であって、**観測**（ファイルを読む・グラフを読む）ではない。

## 理由と捨てた代替案

- **代替案 A: 形不正でも `session.active` が読めれば信用する（現状維持 + 例外）.** 実質これが決定内容だが、`isGraphShape` を呼んだうえで例外を足す形は採らない。「検証してから一部を無視する」より「必要な 1 フィールドだけを読む」ほうが、何に依存しているかがコードから読める（[原則12](../principles/observable-by-design.md)）
- **代替案 B: hook が壊れたグラフファイルを自動で修復・削除する.** 採らない。hook は判定するだけの存在であり、状態を書き換える権限を持たせると「観測のために変更する」ことになる。復帰手段は別に用意する（[ADR 0006](0006-bash-outside-ramune-enforcement.md)）
- **代替案 C: Planner には要約だけを渡し、読み取りは Orchestrator が代行する.** 採らない。何を読むべきかは分解の過程で分かるものであり、事前に列挙できない。Orchestrator が代行すると「読むべきものを Orchestrator が推測する」に置き換わるだけである
- **代替案 D: `isGraphShape` の検査を緩める.** 採らない。MCP サーバーがグラフを書き換える経路では、全体の形の検証は必要である。緩めるべきなのは hook が依存する範囲であって、検証そのものではない

## 影響

- `tools/ramune/graph`: `findSessionActive` を追加して公開する。`isGraphShape` はストア専用として残す
- `tools/ramune/hooks/src/mode.ts`: `isGraphShape` の呼び出しを `findSessionActive` に差し替える
- `tools/ramune/hooks/src/policy.ts`: `Read` / `Grep` / `Glob` をどのロールでも制限しない旨をコメントに明記する（権限表の対象外である事実を、読む人が確認できる場所に置く）
- `.claude/agents/planner.md`: `tools` に `Read` / `Grep` / `Glob` を追加し、「計画の前に仕様書と ADR を読む」ことを明文化する
- グラフモデルにフィールドを追加する変更が、稼働していない worktree を止めることは無くなる。ただし**稼働中**のグラフに対する破壊的なモデル変更は依然として危険である（その run は止まる）。走行中にモデルを変えないという運用は変わらない
